## Fix 2 — 🔴 CRITICAL: Force R:R recompute in LLM engine
**File:** `signals/llm_engine.py`  
**Impact:** Permanently fixes low R:R by recomputing TP levels from entry/SL  
**Effort:** ~30 min

### Problem
When the LLM returns R:R < 1.2, the blended recompute path is supposed to fix it.  
It's not working — signals arrive at filter_gate with original low R:R intact.

### Fix logic
After parsing the LLM JSON, if `rr_ratio < MIN_RR_RATIO`:
1. Take `entry` and `stop_loss` as-is (LLM price levels are usually reasonable)
2. Compute `risk = abs(entry - stop_loss)`
3. Recompute TP1/TP2/TP3 using blended formula to guarantee minimum R:R:
   - `tp1 = entry + (risk × 1.2 × 1.0)` for BUY (flip signs for SELL)
   - `tp2 = entry + (risk × 1.2 × 1.5)`
   - `tp3 = entry + (risk × 1.2 × 2.0)`
4. Recompute blended R:R: `(tp1×0.30 + tp2×0.40 + tp3×0.30 - entry) / risk`
5. Log the override clearly: `[LLM] {symbol} R:R recomputed {old} → {new}`

### Key rule
Never recompute for PASS signals — R:R=0.0 on PASS is correct/expected.  
Only recompute when `signal in ("BUY", "SELL") and rr_ratio < MIN_RR_RATIO`.

## Fix 3 — 🔴 CRITICAL: Fix Liquidation Tracker 401
**File:** `external/liquidation_tracker.py`  
**Impact:** Restores Tier 2 confluence data (liquidation clusters)  
**Effort:** ~20 min

### Problem
```
HTTP 401 Unauthorized — fapi.binance.com/fapi/v1/forceOrders
```
`forceOrders` requires a **signed** Binance Futures API request (HMAC-SHA256 + timestamp).  
Currently sending an unsigned request → always 401.

### Option A — Add proper signing (preferred)
Add `timestamp` + `signature` to the request params using the Binance API secret.  
The `python-binance` or `ccxt` library already has a signed request helper — use it  
instead of raw `requests.get()`.

### Option B — Disable and skip gracefully (quick workaround)
If you don't have a Futures-enabled API key right now:
```python
# external/liquidation_tracker.py
# Add at top of fetch function:
logger.debug("[LIQ] %s skipped — no Futures API key configured", symbol)
return {"liq_long": 0, "liq_short": 0, "cluster": "none"}
```
This stops the 401 spam and lets confluence scoring run without the liq data.

## Fix 4 — 🟡 HIGH: Fix OI Change Always 0.0%
**File:** `data/order_flow.py` or wherever OI is fetched  
**Impact:** Restores Open Interest delta as a live confluence factor  
**Effort:** ~20 min

### Problem
`oi_chg=0.0%` on every asset every cycle.  
Most likely cause: fetching OI at the same timestamp twice, delta = 0.

### Debug step first
Add a log line showing raw OI values before delta:
```python
logger.debug("[OI] %s raw: prev=%s curr=%s delta=%.4f%%", symbol, oi_prev, oi_curr, delta)
```

### Likely fix
Store the previous OI value in a per-symbol cache dict keyed by symbol.  
On each cycle: fetch current OI → compare to cached value → compute delta → update cache.  
If cache is empty (first run), store current OI and return 0.0 (acceptable for cycle 1 only).

## Fix 6 — 🟡 MEDIUM: Normalize HYPE/USDT:USDT symbol
**File:** `config/assets.py` + anywhere symbol strings are used as dict keys  
**Impact:** Prevents mismatch in cooldown tracker, DB storage, TIER1_ASSETS lookup  
**Effort:** ~15 min

### Problem
`HYPE/USDT:USDT` has a double-USDT suffix.  
ccxt handles it fine for API calls, but string equality checks break:  
- `"HYPE/USDT:USDT" in TIER1_ASSETS` — fails if TIER1_ASSETS has `"HYPE/USDT"`
- Cooldown cache key mismatch → cooldown never fires for HYPE
- DB rows stored with inconsistent symbol name

### Fix
Add a symbol normalizer helper used everywhere:
```python
def normalize_symbol(symbol: str) -> str:
    """Ensure consistent symbol format. HYPE/USDT:USDT → HYPE/USDT:USDT (keep futures suffix, strip duplicates)."""
    # Remove accidental double-USDT
    if symbol.count("USDT") > 1:
        base = symbol.split("/")[0]
        symbol = f"{base}/USDT:USDT"  # or USDT depending on spot vs futures
    return symbol
```

## Fix 8 — 🟢 LOW: Checkpoint WAL on startup
**File:** `main.py` or `db/schema.py`  
**Impact:** Makes DB readable from external tools (sqlite3 CLI, monitoring scripts)  
**Effort:** 10 min

### Problem
DB is in WAL mode. The `.db-wal` file (647KB) hasn't been checkpointed.  
`sqlite3 signalforge.db` from CLI sees an empty or stale state.

### Action
Add at startup in `main.py` after DB init:
```python
import sqlite3
with sqlite3.connect("db/signalforge.db") as conn:
    conn.execute("PRAGMA wal_checkpoint(TRUNCATE)")
```
Or configure `PRAGMA wal_autocheckpoint=1000` so it runs automatically every 1000 pages.
