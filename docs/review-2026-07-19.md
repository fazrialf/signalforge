## Part 1 — Trading Strategy Review

### Architecture
ICT/SMC Scalping with Multi-Timeframe Confluence  
Entry logic: BOS/CHOS detection → arm FVG zone → wait for retest → LLM validation → filter gate → delivery

---

### ✅ What's Well-Designed

- **BOS + FVG retest logic** is textbook ICT. CHOS detection → arm zone → wait for price to tap → trigger LLM is the correct sequence.
- **MTF bias layering** (4H macro → 1H structure → 5m/15m entry) is the right hierarchy for scalping.
- **Confluence scoring** with funding rate, OI change, taker ratio, and news sentiment as Tier 3 inputs is genuinely useful for crypto futures — real edge sources.
- **Session filter** blocking alts outside 07:00–22:00 UTC is correct. Asian session fake sweeps on low-cap alts are a real problem.
- **BOS retest TTL at 20 bars** is reasonable — enough time for price to retrace without holding a stale zone.

---

### ⚠️ Strategy-Level Concerns

**1. R:R 1.2 is too tight for scalping**  
With a blended TP structure (30/40/30 across TP1/TP2/TP3), your *effective* R:R on a partial close at TP1 is closer to 0.8–0.9. Scalping crypto futures at 1.2 minimum requires >45% win rate just to break even after fees and slippage. The old 1.5 was borderline — 1.2 makes the strategy fee-sensitive.

**2. LLM is deciding TP/SL levels**  
This is a fundamental weakness. The LLM generates numbers that *look* reasonable but aren't anchored to actual liquidity zones, next FVG, or daily range. The R:R failures (BNB: 0.96, TRX: 0.0) are a direct symptom — LLM places SL too close and TP too conservative.

**3. No HTF (Daily/Weekly) context**  
Strategy tops out at 4H. A bullish 5m scalp against a weekly bearish FVG is low-probability, and nothing in the pipeline catches that.

**4. PASS_COOLDOWN suppression is counterproductive**  
Skipping assets for 2 cycles after 3 consecutive PASSes reduces scan frequency exactly when the market is ranging and you need more data, not less.

## Part 2 — Code Review

### 🔴 Critical Issues (Zero Signals Root Cause)

**Bug 1 — LLM R:R recompute not working**  
`llm_engine.py` has a blended R:R recompute path for when the LLM returns a low R:R, but it is not producing values above 1.2. PASS signals return R:R=0.0; BUY/SELL signals return 0.96–1.1 consistently. Result: `filter_gate._f2_rr_ratio` blocks them all.

```
BNB: Signal=BUY | Confidence=62% | R:R=1.0 → BLOCKED (actual 0.96 < 1.20)
TRX: Signal=PASS | R:R=0.0
SUI: Signal=PASS | R:R=0.0
```

**Bug 2 — Zero FilterGate PASSED events in entire log**  
Not a single signal has passed the filter gate since service start. This confirms the R:R block is catching everything — no secondary filters are even reached.

**Bug 3 — No signals table readable in DB**  
`signalforge.db` is 19MB but the `signals` table returns no rows. DB is in WAL mode (`.db-shm` + `.db-wal` present) — the WAL has not been checkpointed. Also confirms zero delivery history.

**Bug 4 — Liquidation tracker 401 on every call**  
```
[LIQ] BNB/USDT HTTP error: 401 Unauthorized
URL: https://fapi.binance.com/fapi/v1/forceOrders
```
Binance `forceOrders` endpoint requires a signed Futures API key. Failing on every asset, every cycle. Tier 2 liquidation cluster data is permanently missing.

### 🟡 Significant Issues

**Issue 1 — OI change always 0.0%**  
```
oi_chg=0.0% on every asset, every cycle
```
OI enrichment runs but always returns zero. Likely fetching the same OI snapshot twice and computing a delta of zero. Dead data consuming a Tier 3 confluence slot.

**Issue 2 — HYPE/USDT:USDT symbol name is malformed**  
```
[CONFLUENCE] HYPE/USDT:USDT BEARISH
```
Double-USDT suffix. ccxt normalizes this for Binance USDM futures correctly, but string-matching logic (TIER1_ASSETS lookup, cooldown key, DB storage) may break on symbol comparison.

**Issue 3 — Memory at 992MB / 1.1GB max**  
Only 108MB headroom. One high-volatility cycle with all assets hitting confluence simultaneously could OOM-kill the process. systemd restarts it but signals are missed during the window.
